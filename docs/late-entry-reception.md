## 问题和范围

自动接收只调用 VIS 检测；现有扫描时序检测仅在手动选模式时使用。
因此错过开头约 0.91 秒的模式头后，即使后续扫描行清晰，自动模式也无法开始解码。
本轮在已通过四个 CI job 的 `7fb433718325c1b0793bc0a438150d260dbf71ee` 上继续。

目标是锁定并保留仍能收到的图像片段，不是恢复从未收到的像素，也不保证恢复通联文字。
多普勒频偏、采样时钟偏差与漏收 VIS 分开测试；不改变发送格式或声称新增了协议纠错码。

## 实施顺序

1. 先添加 XCTest：15 种模式在图像中途开始、Robot 36 奇偶色度恢复、48 kHz 的晚启动与
   频偏/时钟偏差、持续载波/噪声不误锁、等待缓冲裁切后仍能锁定。
2. 新增接收侧中途模式检测器：使用现有同步脉冲采样器；四个完整同步脉冲的长度、周期、
   频率必须一致。周期误差限于 ±0.5%，不能把 Robot 36 隔行同步误判为 Robot 72。
   多个非倍频候选冲突时继续等待，不按枚举顺序猜模式。
3. 自动模式优先 VIS，失败后按节流周期检查中途候选。游标避免反复扫描全部历史；
   等待缓冲保留足够的 Scottie DX 行，仍有明确内存上限。
4. Robot 36 用 1500/2300 Hz 色度分隔标记确认行对，从完整 R−Y / B−Y 行对开始，
   不改色彩矩阵或发送端；已有手动入口和 HF Fax 保持独立。
5. 帧元数据标记“中途锁定”，界面展示已解码行数和“原始行号未知”，不冒充 VIS 已识别，
   不给出虚假的整图完成率；保留片段 PNG 导出。
6. 版本提升为 1.1.3（5）。Windows 只运行脚本/契约检查；Swift、App 编译和固定 WAV
   哈希验证交给 Actions。推送原修复分支后立即报告 run 链接，不等待、不自动合并。

## 不变项与验收边界

- 编码器、VIS 码表、模式定义、发送时序、色彩转换、重采样、冻结 WAV 哈希不变。
- 现有完整帧、画质、抗谐波、同步与麦克风连续性测试全部保留。
- 缺失原始行号不能确定漏收了多少行；片段从首个可确认的完整行显示，不伪造顶端补全。
- 本轮不把短时信号中断等同于任意长度断流恢复；不扩大到多帧图库或完整 UI 改造。
- 真实卫星链路、多普勒范围、弱信号和设备性能仍需原始录音/真机验证。

协议依据：[Image Communication on Short Waves，第 4 章](https://www.sstv-handbook.com/download/sstv_04.pdf)：
Robot 色度分隔标记用于中断后的重新同步；Martin 行同步支持在传输中途取得同步。
