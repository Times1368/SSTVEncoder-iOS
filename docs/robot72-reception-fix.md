## 本次修改

1. **混频前抑制谐波。** 原来只在正交混频后滤波：1500 Hz 信号的二次谐波
   3000 Hz 经 1900 Hz 混频后落到 +1100 Hz，仍在原低通范围内。
   新增实际音频域 2500 Hz 低通，48 kHz 时为 201 taps / 100 样本延迟；
   原混频滤波不收窄，总延迟由 80 变为 180 个样本，并交给现有采样器补偿。
   滤波状态跨块连续，不逐样本分配数组。
2. **同步不再只看平均频率。** 检查稳定内部、离散程度、有效样本比例及脉冲内外支持度，
   防止高低频干扰恰好平均成 1200 Hz 就被当成同步。频偏来自排除边缘后的稳定内部，
   不让前一像素和后一 porch 的过渡污染校正值。
3. **恢复行时钟。** 使用保留小数样本的二阶行时钟，相位增益 0.2、周期增益 0.01，
   周期限制在标称值的 ±0.5%。相位不逐行照搬单个同步点的抖动；短时丢同步沿已恢复
   周期预测。实际周期比例应用于解码扫描位置和采样窗口，不改发送时序。
   未完整收到一行时只操作状态副本，避免重复 append 积累校正。
4. **音频连续性变成硬条件。** 保留 AVAudioTime 的样本时间戳；有界队列保留连续前缀，
   溢出时明确抛错，不丢旧块后悄悄拼接。时间缺口、重复或设备时钟重启在 append 前拦截，
   停止并保留部分图像。没有有效硬件时间戳时不伪造连续性证明，队列溢出检测仍生效。
5. **错误清理归当前会话所有。** 先验证会话 generation，再关闭麦克风，避免旧任务的
   错误回调关闭用户新开的接收会话。原始音频不保存、不上传；开麦仍要求用户点击。

编码器、VIS 表、发送行时序、RGB/YCrCb 转换、重采样和图片载入器保持不变。
`SSTVFrameAssembler` 仅调整同步/时钟及采样尺度，原各模式像素写入与色彩计算不变。

## 验证方法

先添加 XCTest，再实现对应修改。Windows 没有运行任何 Swift/Xcode 命令；
下面的模型数字不能替代 CI 的 XCTest 结果。

- 在标准库数值模型中，基波振幅 0.6、二次谐波 0.12、三次谐波 0.06；
  48 kHz、约 0.19 ms 窗口：1500 Hz 的最大误差由约 285.671 Hz 降至 2.074 Hz。
  1700/1900/2137/2300 Hz 的新模型最大误差均低于 0.06 Hz。
  孤立 9 ms 同步的测量均值约 1204.828 Hz，未放宽原 ±12 Hz 测试要求。
- 240 行时钟模型中，输入同步位置交替抖动 ±24 样本，稳定后输出位置极差约 5.248 样本；
  ±1000 ppm 周期偏差、五行缺同步的指定用例在稳定后误差小于 1 样本。
- 这些是明确定义的合成输入，不是用户录音；没有用 Python 生成或替换 Swift WAV 基线。

新增/扩展 CI 覆盖：

| 用例 | 判据 |
|---|---|
| 12/44.1/48 kHz 谐波干扰的五个像素频率 | 最大短窗口频差 ≤5 Hz |
| 相互抵消的双频干扰 | 不能被判为稳定同步脉冲 |
| 同步边缘受污染 | 稳定内部频偏误差 ≤1 Hz；位置误差 ≤4 样本 |
| 240 行抖动和时钟偏差、缺同步 | 固定时钟测试门槛，不通过时不临时放宽 |
| Robot 72 的 44.1/48 kHz 清晰图样 | 加入已有多模式质量测试 |
| Robot 72 的 48 kHz 完整 240 行 | 必须完成，保留全部行的色差和竖边检查 |
| Robot 72 的 64 行扰动序列 | ±1000 ppm 时钟偏差、+120/-100 Hz 频偏及固定种子噪声 |
| 麦克风队列溢出和硬件时间缺口 | 保留连续前缀，抛出明确错误，不悄悄续接 |

原图样判据保持：排除前两行及色块边界各 6 像素，测量分量平均误差 ≤12/255、
最大分量误差 ≤24/255、逐行竖边极差 ≤2 像素、绝对偏移 ≤4 像素。
新增 JSON 字段记录 scenario、clockScale、addedFrequencyOffsetHz、noiseAmplitude；
各情形使用不同文件名，CI 保留 source/decoded PNG 和误差报告。

原三份编码 WAV 仍在 Swift 5.9 Release CI 对照冻结哈希；失败不更新基线。
本分支在通过兼容性和当前工具链测试后才打包 unsigned IPA，再下载复核。

## 下一步实测与未覆盖项目

应使用相同发送图、Robot 72、相同设备与输入条件对比 1.1.1/1.1.2，提供完整 PNG
而非只截接收到一半的页面。有原始 WAV/CAF 时，先走文件导入隔离采集变量；
不要把用户音频或设备照片直接上传到公开仓库。

尚未验证：真实手机扬声器/麦克风、削顶或严重混响、真实无线电噪声、最低支持机型
的实时 CPU 和队列压力。新增滤波会增加计算量，真机性能是独立门槛。
断流现在会明确停止，不代表已实现断流自动恢复或连续多帧入库。
图库、连续接收和完整 UI 仍按原计划后续实施，不因本次修复取消。

协议背景：[Image Communication on Short Waves，第 4 章 Robot 模式](https://www.sstv-handbook.com/download/sstv_04.pdf)。
队列行为：[Swift AsyncThrowingStream bufferingOldest](https://developer.apple.com/documentation/swift/asyncthrowingstream/continuation/bufferingpolicy/bufferingoldest(_:))。
