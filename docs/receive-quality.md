## 问题证据与修复范围

旧解调器在正交混频后使用三级单极点滤波器，残留的混频镜像会在短像素窗口内
造成频率估计波动。独立数值模型以 48 kHz 采样、1500 Hz 恒定正弦和约
0.19 ms 窗口测得：旧结构最大窗口误差约 146.322 Hz，新结构约 0.119 Hz。
这只是数学模型对滤波方案的对比，不是运行 Swift 的结果，不是原始用户录音，
也不能据此断定实际图片弯曲的原因。模型没有生成任何基线 WAV。

新结构采用归一化、奇数长度、对称的 Blackman 窗 sinc FIR：

- 48 kHz 时 161 taps，滤波器群延迟为确定的 80 个样本。
- 系数按采样率生成；低采样率收窄截止频率，避免折叠回来的混频镜像。
- 振荡器、滤波历史和相位状态跨音频块保留；环形缓冲与对称卷积不逐样本分配。
- 非有限输入按零处理，避免 NaN/Inf 永久污染后续滤波状态。
- 接受 6000–384000 Hz，拒绝不合理的大采样率以约束系数生成和内存分配。
- 生产目标仍只依赖 Foundation，没有复制第三方实现或引入运行库。

滤波器数学依据：[Steven W. Smith，Windowed-Sinc Filter Design](https://dspguide.com/ch16/2.htm)。
固定群延迟解决滤波对齐的一项不确定性，不等于已实现采样时钟恢复。

## 自动化验收

保留现有解码、头检测、分块一致性、HF Fax 和 App 测试，不删除或放宽旧断言。
新增 XCTest：

| 测试 | 范围与固定判据 |
|---|---|
| 短窗口频率 | 6/12/44.1/48 kHz；1200/1500/1700/1900/2137/2300 Hz；稳定区最大误差不超过 2 Hz |
| 异常样本恢复 | 输入 NaN/Inf 后，正常音频仍恢复为有限且正确的频率 |
| 色块与几何 | 15 个 VIS 模式各 12 kHz；Robot 36、Martin M1、PD 120 另测 44.1/48 kHz |
| 多行图样 | 16 条无线电扫描行，PD 对应 32 行像素；宽色块与每四行变化的灰块 |
| 色块判据 | 预先排除前两行、色块边界两侧各 6 像素；全体测量分量平均误差 ≤12/255，最大分量误差 ≤24/255 |
| 几何判据 | 不先重对齐图片；每一测量行都必须找到黑到灰的竖边，行间位置极差 ≤2 像素，绝对偏移 ≤4 像素 |
| 编码保护 | 原生坐标图通过 Swift 编码，Robot 36 / Martin M1 / PD 120 的 WAV 哈希必须等于冻结基线 |

图样测试直接使用现有 Swift 头/行编码器生成短测试音频，并通过流式解码器消费。
它们是有意加强的合成自环测试，不能替代独立编码器的全帧互操作音频、
用户失败录音、弱信号或采样缺口测试。

## CI 证据与发布门槛

- Xcode 15.0.1 / Swift 5.9：Release SwiftPM 测试，启用冻结 WAV 哈希检查。
- Xcode 16.4：保留 Debug SwiftPM 测试；精确 WAV 哈希测试明确跳过，避免把工具链差异直接归为算法回归。
- 两条线分别上传 `receive-quality-xcode15-<commit>` 和
  `receive-quality-xcode16-<commit>`，保留 30 天。
- 每组图样输出 `*-source.png`、`*-decoded.png`、JSON（色差、行数、逐行边缘位置、频偏）；
  在质量断言之前写盘。解码本身若抛错，错误以测试日志为准，不能将缺失报告视作通过。
- `toolchain.txt` 记录实际 Xcode、Swift、目标架构、提交和构建配置。
  Swift 5.9 产物还含 `encoder-check/` 中三个重新验证的 WAV 与 SHA256SUMS。
  [冻结哈希的来源与环境](../Tests/Baseline/README.md) 单独记录，原始产物不被覆盖。
- 兼容性、当前工具链测试、unsigned IPA 打包、下载后独立校验仍按顺序设硬门槛。
  没有 `continue-on-error`，不合并红色 CI。

Windows 仅运行 Python 仓库/打包验证脚本及静态检查，不能据此声称 Swift 编译、
iPhone 实时性能或实际收图通过。推送后交付 Actions 链接，不等待结果，不自动合并主干。
